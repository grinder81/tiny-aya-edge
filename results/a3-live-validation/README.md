# A3 supported-client live validation

The unchanged upstream `LocalCompletionsAPI` passes independent cold-logit and
request-order checks with a separately pinned wrapper runtime. No custom adapter
or scorer is used. These are runtime diagnostic cases, not accuracy estimates or
a canonical-contract decision. The full variant comparison follows a reviewed
upstream-runner PR; the user still selects the downstream contract before B5.

## Preserved execution history

- **v1 failed:** independent cold forwards completed all 192 candidates. The
  bounded HTTP check stopped after seven complete records because reused-prefix
  chat probabilities differed from cold logits, despite exact echo strings and
  counts. Supplied-prompt errors reached 0.18238 nats; tested chat continuation
  differences reached 0.02854. Four initial plain-letter candidates matched A2
  exactly. Fresh-server permutations also changed plain/chat likelihoods.
- **v2 incomplete explanation:** seven same-order supported-wrapper completions,
  with independent full-vocabulary float64 log-softmax from raw `_scores`, matched
  those preserved HTTP arrays within 9.3e-7 nats. This isolates execution-history
  dependence from the echo/parser alignment question; it is not a full gate.
- **v3 incomplete:** a separate cold-prefill runtime removed the observed failure.
  The slow HTTP check was stopped when exact top-one ranking was identified as a
  bottleneck. Its cold direct-oracle records are exactly equal to all 192 v4 BF16
  records. The original environment and raw outputs remain intact.
- **v4 complete:** both arms passed the full 192-candidate probability gate and a
  separate 36-candidate reversed-order gate. The final runtime combines cold
  echoed-likelihood prefill with an exactly equivalent top-one ranking fast path.

Protocols were frozen before their respective requests in

## Complete v4 evidence

Each arm covers the same fixed 48 contexts: every language, variant and rotation
at index zero, plus the longest full inputs and continuations per language and
variant. All four candidates are checked. The separate reversed-order stress test
uses nine fixed language-by-variant index-zero/rotation-zero contexts, all four
candidates. Token IDs, single automatic BOS, echo strings/counts, and exactly one
generated suffix must match; numerical tolerance never excuses misalignment.

| Quantity | BF16 GGUF | Local Q4 |
|---|---:|---:|
| Primary candidates / contexts | 192 / 48 | 192 / 48 |
| Reversed candidates / contexts | 36 / 9 | 36 / 9 |
| Maximum supplied-echo error, nats | 1.643e-6 | 1.805e-6 |
| Maximum continuation-token error, nats | 1.321e-6 | 1.318e-6 |
| Maximum summed-continuation error, nats | 2.281e-6 | 1.916e-6 |
| Maximum generated-suffix error, nats | 3.474e-7 | 3.337e-7 |
| Repeated cold-forward error | 0 | 0 |
| Correctness failures / argmax inversions | 0 / 0 | 0 / 0 |

Both per-token 0.0002-nat and summed max(0.001, continuation tokens × 0.0002)-nat
bounds apply. The unchanged parser also matches the same supplied echo slice to
1e-8. Raw responses, independent reference probabilities, every per-candidate
comparison and predictions/margins are in `v4/`; `summary.json` is generated by
`setup/summarize_a3_validation.py`. `evidence-index.json` pins every copied byte
artifact and retained raw-source identity. JSON files are marked `-text`.
Large committed JSON copies use lossless `.json.gz` storage; the index records
both compressed hashes and the original decompressed bytes/hashes. Uncompressed
raw originals remain at the retained WSL root. Run `setup/verify_a3_archive.py
--directory results/a3-live-validation` to verify every original byte identity;
ordinary Python `gzip.open(path, 'rt')` reads an individual archived JSON file.

The legacy A2 bridge is deliberately separate. Among 60 plain-letter candidate
scores in 15 selected contexts per arm, 42 BF16 and 55 Q4 differences exceed the
original 0.001-nat bridge bound. Maximum absolute differences are 0.047802 and
0.424250 nats respectively. No selected-context winner changed. These observations
do not establish equivalence or preserve all historical predictions. Old A1/A2
identities remain historical; new A3 plain-letter scores are an independent cold
diagnostic baseline. Reused-prefix execution is an additional potential confound
in interpreting old option-rotation changes, not proof that it explains them all.

Both recorded A2 Python-server commands actually use effective BOS 2 and EOS 6.
The older conversion manifest requires EOS 3; that discrepancy is explicit here.
V4 preserves the A2 metadata behavior rather than silently adding an override.
Candidates append no EOS, and the one generated suffix was checked in every
probe. This does not ratify EOS 6 for future generation experiments.

## Runtime, tests and reproduction

The original `/home/shohag/tiny-aya-stage1/llama-python-compat` is untouched.
`setup/prepare_a3_scoring_runtime.py` clones that hash-checked environment into a
new directory and applies `python-cold-echo.patch` then `python-echo-top1.patch`.
The recorded final import path and interpreter prefix both point to
`llama-python-a3-cold-fast`; wrapper SHA256 is
`114c18646074b3ada403ac2963d12d298bb45b354329cb1d0e95e8bd072fdc8b`.
Both final manifests pin model, native library, wrapper/server sources, patches
and protocol. The isolated upstream client and tokenizer remain unchanged.

The cold guard test passes 12 echo/logprobs/cache combinations and checks ordering
before generation. Echo scoring bypasses cache restoration; cache writes may
still occur. Nonscoring branches are unchanged. The exact top-one patch passes
76 selection and 360 complete echo-dictionary comparisons, including ties,
signed zero, infinities and NaNs. Existing seven decode-buffer cases and 12 echo
ranking comparisons also pass. CPU ranking speed is not model throughput.

Primary client wall times were 109.26 seconds for BF16 and 79.83 for Q4, including
initialization, source checks and evidence validation. These are not tokens/sec
or a phone-performance measurement.

To reproduce, create a new environment and new output directory, never overwrite
these identities. Run the installer with the original environment, both patch
paths and pinned library directory; create each arm manifest with
`setup/create_a3_cold_manifest.py`; run `setup/validate_a3_cold.py direct`, then
`client` on a fresh matching server, then `client --order-check` on that warmed
server. All scripts require explicit input/output paths. The retained raw root is
`/home/shohag/tiny-aya-stage1/pilot/scoring-control/`. No holdout was accessed.
