# Bounded resource profile for the Tiny Aya pilot

1 November 2026. This specification precedes the G1 forwards in [issue 42](https://github.com/grinder81/tiny-aya-edge/issues/42). It profiles existing BF16 and Q4 artifacts; it does not select C8 sites or compare language-specific sensitivity rankings.

Use only original development index 0 in each of English, Bangla and Hindi from the T1 request lock, SHA256 `6dfdd304dcba7bd772c37a7634e74c0c16d1e4b70728be6dcb0e218f3847aa19`. Do not truncate these three prompts. The holdout and A4 slices remain sealed. Their language-level KL values are descriptive feasibility evidence and cannot select the later C8 tensor subset, formats or thresholds.

Load each existing model sequentially through the exact T1 v4 runtime manifest. Verify every model/runtime file hash and actually imported module path. Verify full prompt IDs and compare all four final letter log probabilities with the hash-verified T1 report, within 0.0002 nats. Stop on failure. Use fresh prefill and the original model settings; no server or competing GPU job runs alongside the direct process.

Cache raw BF16 logits as float32 arrays for just these three prompts, excluding the final prediction beyond the prompt. For a prompt with BOS plus T content tokens, compare distributions at rows 0 through T-1, the predictions for the T content tokens. Compute KL(BF16 || Q4) and top-1 agreement with float64 full-vocabulary normalization in chunks of at most 8 token rows. Average tokens within each question. Check the implementation against an independent full-array oracle and identity KL on synthetic fixtures before model use. Preserve hashes, shapes and timing for caches; do not cache full-dataset logits during G1.

Report model load time, each forward time, cache bytes and write/read time, KL reduction time, CPU maximum RSS and GPU usage observed at stage boundaries. Boundary samples are not a measured peak VRAM trace. Estimate the full-900 raw float32 cache from the exact lock token lengths, and disclose that projection separately from measured three-prompt cost. The entire G1 direct profile has a 30-minute cap; preserve failure or partial evidence and stop rather than silently changing settings.

The empirical Fisher readiness check uses the pinned source checkpoint in the existing differentiable environment. It will first verify token/weight correspondence and measure forward/backward feasibility on one separate profiling example. Its proposed estimator is the mean across examples of the squared gradient of mean next-token negative log-likelihood per example, excluding BOS and padding; this is explicitly a sequence-level empirical Fisher proxy, not token-wise Fisher or the exact output KL Hessian. Per-example squaring occurs before averaging. Freeze actual text membership, token truncation and differentiable-path equivalence tolerances before that backward pass. G1 does not automatically authorize replacing measured KL with this score.
